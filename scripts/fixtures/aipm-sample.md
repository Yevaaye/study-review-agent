一、角色定位与能力模型
1.1 AIPM 的定义与边界
AI 产品经理是负责"用 AI 能力解决用户问题、并把概率性系统做成稳定产品"的人。与传统 PM 最大的不同：传统 PM 交付的是"确定的功能逻辑"，AIPM 交付的是"带方差的体验"。
边界澄清：
一、AIPM 不是算法工程师：不必会训练模型，但必须能判断"这个场景该用 Prompt / RAG / 微调 / Agent 哪种范式"。

1.4 典型误区
误区 1：把 AI 当万能锤。什么功能都"加个大模型"，结果成本高、效果飘、用户不买账。
1.5 职业进阶路径
1. 入行：懂业务 + 基础 AI 概念，能从 0 写 AI 功能 PRD。
2. 进阶：主导范式选型、搭建评测体系、跑通数据闭环。

2.2 大模型（LLM）原理速通（PM 视角）
Transformer / Attention：模型能"关注"输入中相关的部分，是长文本理解的基础。
Token：模型处理文本的最小单位（中文约 1-2 字=1 Token）。
2.3 四大落地范式深解与选型
（1）Prompt 工程
原理：不训练，仅靠精心设计输入指令引导通用模型。
（2）RAG（检索增强生成）
原理：先把知识切分存入向量库；用户提问时检索相关片段，拼进 Prompt 让模型基于"给定资料"回答。

3.3 数据闭环飞轮
上线不是终点，闭环才是。标准飞轮：
用户使用 → 采集行为/反馈 → 标注/清洗 → 训练或优化(Prompt/RAG/微调) → 评测 → 上线 → （回到使用）
3.4 冷启动策略
初期数据少：用规则/人工补位顶上，先跑通流程、积累真实数据。
3.5 概率性体验设计原则
降低预期落差：明确"AI 可能不准"，而非假装全能。
四、产品设计落地
4.1 可解释性设计
用户信任来自"看得见依据"：
引用来源：回答里标注出自哪段原文/哪个知识块（RAG 天然支持）。
4.2 Guardrails 护栏体系
输入层：敏感词过滤、越权/注入拦截（防 Prompt 注入）。
输出层：内容安全审核（涉政/暴恐/色情/违规）、格式校验、拒答兜底。
4.3 降级与容错
模型挂了/超时：回退到规则答案、缓存答案或"人工通道"，主流程不崩。
4.4 成本工程
每次推理都有算力成本，PRD 必算：
单请求成本 ≈ (输入 Token + 输出 Token) × 单价。
4.5 Prompt / 知识库 / 评测集的版本管理
这三个是 AI 产品的"配方"，要像代码一样版本化。
五、评估与迭代
5.1 离线评测体系
评测集（golden set）：人工标注的"标准答案库"，覆盖典型与边界 case。
5.2 在线指标体系

5.3 Badcase 复盘机制
建 badcase 库，每条含：输入、输出、错误类型、根因、处理方式。
5.4 A/B 与灰度发布
AI 输出方差大，绝不全量直推。
5.5 回归测试
每次迭代保留"历史好 case"作为回归集。
六、合规与商业化
6.1 数据安全与隐私
训练/检索数据脱敏：PII（个人身份信息） anonymize，不进模型。
6.2 合规框架（国内）
内容安全：生成内容必须过审核，防涉政/暴恐/色情/违规，平台有责。
算法备案：部分具有舆论属性或社会动员能力的算法需向网信办备案。
6.3 幻觉责任与风险
ToB / 专业场景：明确"AI 仅供参考"，关键决策留人审。
6.4 商业模型与成本测算
收费模式：按调用量计费、订阅制、增值服务、按效果付费。
七、行业场景深解
7.1 智能客服 / 问答
范式：RAG + 知识库为主。
痛点：幻觉、知识更新滞后、多轮理解差。
7.2 内容生成（文案/报告/代码）
范式：Prompt / 微调。
痛点：一致性差、风格漂移、合规风险。
7.3 推荐 / 搜索
范式：传统 ML + LLM 重排/理解。
7.4 办公自动化 / Agent
范式：Agent + 工具调用。
7.5 数据分析 Copilot（NL2SQL）
范式：自然语言 → SQL → 图表。
